Naivas DemoPractice data made up for this demo. Not Naivas's real numbers.

Same sales. Two different profit reports.

In a chain with 100+ branches, product codes, units and prices get recorded in slightly different ways. The report then shows the wrong profit, and analysts lose days fixing files. This demo takes a set of messy branch sales, cleans it automatically, and shows the report before and after.

One sales line below means one product's sales at one branch in one week.

1. The problem: seven kinds of mistake

These were added to the practice data on purpose, at realistic rates, so we know exactly where they are.

2. What the mistakes do to the report

The raw report finds each sale's cost by exact product code. When the code doesn't match, the sale lands in "Unmapped" with no cost, so it looks like pure profit.

Eight weeks, twelve branches, forty products. Sales that differ by more than 5% are in red. KSh = Kenya shillings, M = millions.

3. What this does to fix it

  1. Match every code. nv-1042, 1042-NV and NV1042 are all turned into NV-1042 and matched to the product list.
  2. Put units back to one standard. Dozens become single items, and litres become the pack count.
  3. Catch wrong prices. A price ten times the shelf price is corrected.
  4. Use the supplier's latest cost. Where the system's cost is out of date, the supplier's cost is used.
  5. Don't guess the rest. Unknown codes and negative quantities go to a person, with their value shown.

See it for one product. Pick a product to see every way its code was written, all matched back to the right one.

4. Did it catch the mistakes?

Because we know every planted mistake, we can check the cleaning against the answers.

Some mistakes can't be caught by rules. About one in seven wrong codes was a typo that lands on a different real product, so it looks valid. Catching those needs an extra check against typical price or sales for that product, which is the next rule to add. Real data is also messier than this demo, so real scores would be lower and the rules would need tuning.

5. What the team can do next

With numbers they can trust, the work moves from fixing files to making decisions.
